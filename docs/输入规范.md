# 输入规范 / Input contract

本模块消费原课题已经处理的细胞 subset 与注释，不重新聚类、不重新 QC、不自动发明亚群名。它校验文件结构和 raw counts 的基本完整性；这些检查不能证明原课题的细胞身份或生物学结论。

统一接口为 `load_input(spec, base_dir)`，返回 `(counts, gene_symbols, cell_metadata, provenance)`。`counts` 是 **细胞×基因**的 SciPy CSR；`cell_metadata` 按实际 counts 的细胞顺序排列，保留原字段，并增加或校验 `cell_id`、`sample_id`、`donor_id`、`vpt_state`。其中 `vpt_state` 仅复制原课题通过 `columns.state` 指定的字段。相对路径均相对于配置文件所在目录 `base_dir`。

## 必须说明的来源

每次输入必须填写 `species`、`accession`、`counts_origin`、`qc_status` 与 `annotation`。`annotation.kind` 只允许 `operational`、`author`、`validated`，同时填写 `label`、`source`。这只是来源声明，不由加载器认证；`validated` 必须能对应原课题的独立身份证据。禁止为了通过接口把 provisional 注释改称 validated。

必须可靠提供细胞、样本、供者和状态字段。供者未知时可保留空值或 `UNKNOWN`，模块不会生成供者 ID，`provenance.donor_stratification_allowed` 为 `false`，后续不得运行供者分层分析。样本 ID 缺失直接阻止加载。已知供者和文库不是同义概念，同一供者的多个文库不能作为独立生物学重复。

`qc_status` 完整保留原声明；加载器不将任意非空字符串认证为 QC 合格。生物学用途是否允许需要审查原课题。状态是 operational 或未知时，保留警告并阻止把结果写成“该亚群特异性”；这不等于阻止使用明确标注的探索性 subset。

统一 CLI 另要求配置中的 `input.qc_completed=true`，明确声明上游 QC 已完成；这不是 loader 自动 QC 或自动认证身份的标志。若数据仍未完成 QC，不得为了启动模型填写 true。`load_input()` 本身不强制这个 key，准入由 CLI 执行。

## 10x MTX：本次真实历史示范使用的接口

目录内分别只允许一份 `matrix.mtx[.gz]`、`features.tsv[.gz]`、`barcodes.tsv[.gz]`；同名压缩与非压缩文件同时存在会阻止加载。10x 文件为 **基因×细胞**，加载后转成细胞×基因。features 第一列保留原 feature ID，第二列是来源明确的 gene symbol；不推测 Ensembl，不自动合并同名基因。混合非 RNA features 应由原课题提供清晰 RNA subset。

在调用 `mmread` 之前先流式读取 MatrixMarket header、维度与 nnz，只接受 general sparse coordinate integer/real，按 `64*nnz + 16*(genes+cells)` 字节保守预估 COO、CSR 与转换临时数组，超过 `max_counts_bytes`（默认 256 MiB）即停止，不能先加载大矩阵再检查。此限额仍不是整个进程峰值；10x 应由原课题提供小型已处理 subset。

```json
{
  "format": "10x",
  "path": "../../PI_Inflammatory_Fibroblast_Virtual_Perturbation/data/10x_target",
  "cell_metadata": "../../PI_Inflammatory_Fibroblast_Virtual_Perturbation/data/metadata/cell_metadata.csv",
  "gene_metadata": "../../PI_Inflammatory_Fibroblast_Virtual_Perturbation/data/metadata/gene_metadata.csv",
  "columns": {
    "cell_id": "cell_id",
    "sample_id": "sample_id",
    "donor_id": "donor_id",
    "state": "operational_state"
  },
  "species": "Homo sapiens",
  "accession": "zenodo.19697597",
  "counts_origin": "canonical layers/counts; exact historical 10x export",
  "qc_status": "upstream provisional QC; see historical audit",
  "qc_completed": true,
  "annotation": {
    "kind": "operational",
    "label": "Inflammatory_enriched",
    "source": "historical frozen_multigene_v1; author fine annotation unavailable"
  }
}
```

CSV 必须通过真实 cell ID 与 barcode 精确连接，可按 barcode 顺序可靠重排；缺失 ID、重复 ID 或冲突字段均失败。不能借助聚类或推测列顺序建立映射。元数据多于本次 counts 的行可保留在源文件中，加载器只选择确实匹配的行。

可选 `gene_metadata` 用明确 ID 对齐，默认 `gene_id_column=feature_id`、`gene_symbol_column=gene_symbol`。CSV 中的 symbol 必须与矩阵 features 的真实标识对应；不会按位置凑齐或自行改名。原 ID 顺序记录于 `provenance.source_gene_ids`，完整源表与 SHA-256 路径一并记录。

## H5AD：明确读取 counts layer

指定 `format=h5ad`、`path`、**显式** `counts_layer=counts`。如 gene symbol 不在 `var_names`，必须提供来源明确的 `gene_symbol_column`。支持 obs 原字段映射，默认 `obs_names` 为细胞 ID；如果 obs 的指定 ID 列与 `obs_names` 顺序矛盾，直接失败，不推测改名。基因始终跟随 var 的原顺序，不重新排序。

`X`、`raw`、`raw.X` 不被猜作 counts，也不接受为本接口的 counts layer。只做非负整数检查无法区分一种恰巧为整数的归一化矩阵，故来源声明仍必须真实。用户须在原课题准备明确的原始 counts layer。

使用 `h5py` 与 AnnData 官方 `io.read_elem` / `io.sparse_dataset`，先读 obs/var 和冻结的 `selection`，再读取 counts 的目标行，避免 `read_h5ad(backed='r')` 对 layers 可能产生的整层加载。例：

```json
{
  "format": "h5ad",
  "path": "D:/project/processed_subset.h5ad",
  "counts_layer": "counts",
  "qc_completed": true,
  "gene_symbol_column": "gene_symbol",
  "columns": {"sample_id": "sample", "donor_id": "donor", "state": "author_state"},
  "selection": {"column": "celltype", "values": ["Fibroblast"]},
  "max_counts_bytes": 268435456
}
```

此片段仍须补齐上述来源和 annotation 字段。`selection` 只筛选已有的标签，不重新定义细胞身份；同一配置下冻结使用，不根据预测结果换 subset。默认 counts 切片内存估算上限 256 MiB，可用 `max_counts_bytes` 收紧；这不是整个进程的峰值上限。CSR 按目标行估计 nnz；CSC 因行切片可能读取全矩阵而保守按全 nnz 估计。完整大对象的 obs/var 仍会占内存，资源很低时应由原课题提供已处理的小 subset。

本次以小型软件夹具实际测试了 10x↔H5AD values、细胞顺序和特征顺序一致性，缺失 layer、重复 symbol、非法 counts 与切片预算阻断。没有重新读入大 Atlas。

## Seurat RDS：显式导出适配器，当前未实测

脚本 `scripts/export_seurat.R` 只使用已经安装的 `SeuratObject`、`Matrix`、`jsonlite`，不安装依赖，不修改源 RDS。先检查原环境，再执行：

```powershell
Rscript scripts/export_seurat.R D:/project/processed_subset.rds D:/project/vpt_counts_export RNA
```

输出目录必须为空。脚本只接受稀疏、有限、非负整数的 RNA counts；Seurat v5 要求单一明确的 `counts` layer，split counts layers 会停止，须由原课题解释和准备一致的导出，不能在此自动 JoinLayers。v4 使用 `slot=counts`。features 保留 Seurat 原 row names；没有 symbol 证据时不会发明映射。若原 row names 是 Ensembl，需在原课题之外准备来源明确、可审查的 symbol 对应导出后再用于基因 symbol 靶点，当前适配器不自动转换。

配置使用 `format=seurat_rds`，`path` 指向原 RDS，`export_path` 指向导出目录，仍提供 sample/donor/state 列映射和来源声明。Python loader 校验 `seurat_export_manifest.json` 的源 RDS MD5 及四份导出文件 MD5，然后走同一个 10x loader；可以通过 `cell_metadata` 指定已有的可靠补充元数据 CSV。

当前代码接口已准备，**未在本机用实际 Seurat RDS 执行验证**，不能标记为 RUN_OK。没有导出路径时明确阻断，不自动调用 R 或安装 Seurat。MD5 用于匹配现有 R 导出，不作为安全签名；加载成功后另记录 SHA-256 用于研究追溯。

## 错误、警告与科学边界

非法 counts、重复 gene symbols、缺失/重复 cell IDs、错误维度、缺失 counts layer、空 subset、来源声明缺失，均阻止加载。零 counts 细胞在 loader 中原样保留并警告，统一 CLI 会阻止建模；交由原课题 QC 解决，不静默删除。所有原始输入保持只读；大矩阵只使用外部路径，不复制。

配置可选 `input.sha256`，以实际绝对源文件路径为 key、预期 SHA-256 为 value。统一 CLI 将其与本次 provenance 中实际消费的全部文件严格匹配；缺文件、额外条目或哈希变化均停止。该校验不会证明样本身份或 count 来源正确，只保证明确指定的输入未变化。

输入成功只支持结构与来源审查这一层。不能据此宣称虚拟 KO 等同于真实 CRISPR/siRNA，不能自动标记 `PREDICTION_STABLE` 或 `BIO_VALIDATED`。测试夹具只证明软件契约，不提供任何生物学验证。
